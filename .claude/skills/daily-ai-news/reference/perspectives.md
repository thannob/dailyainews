# Perspectives — 2026-09-16

## 1. Salesforce/Nvidia เปิดตัว Koa — โมเดล reasoning เฉพาะทาง CRM

**อาจารย์ (มหาวิทยาลัย):** เคสนี้ดีสำหรับคาบ ML engineering — ให้นักศึกษาเปรียบเทียบ **specialization strategy** (post-train บนโมเดลเปิด Nemotron 3 Super ด้วย synthetic data จาก 30 ปี CRM deployment) กับ **generalist frontier model** (GPT-5.x, Claude Fable 5.1) ในมิติ cost, latency, และ domain fidelity บนงาน enterprise workflow ที่ซ้ำแบบ.
**ผู้เชี่ยวชาญด้าน AI:** ประเด็นเทคนิคที่น่าจับตา — SFT + RL แบบ GRPO บน NeMo Gym แสดงว่า **synthetic-data reasoning training** โตพอที่ post-training team ระดับ enterprise ทำเองได้แล้ว โดยไม่ต้อง scratch pretrain; และ "no customer data" คือ compliance play ที่ตัดกำแพง GDPR/APPI/PDPA ก่อนขายเข้า regulated industry.
**โปรแกรมเมอร์มืออาชีพ:** ถ้าใช้ Salesforce/Agentforce อยู่ Koa จะเข้ามาเป็น backend reasoning ของ agent ใน tenant ตุลาคมนี้ — เตรียม (1) audit tool schema ที่ agent เรียก เพราะโมเดลใหม่ tune ให้เลือก tool ต่างจาก generalist, (2) rerun eval golden set ก่อน rollout เพราะ error mode ของ specialized model ไม่ตรงกับ Claude/GPT ที่เคย benchmark.

## 2. OpenAI/Anthropic/Google DeepMind ประกาศ coordinate AI safety

**อาจารย์ (มหาวิทยาลัย):** ในคาบ competition/antitrust law จับประเด็นที่ Chris Lehane บอกว่า **"ไม่ต้องขอ antitrust waiver"** — เทียบกับกรณี Frontier Model Forum (2023) และการ coordinate ราคายาระหว่างบริษัท pharma; นักศึกษาต้อง identify เส้นแบ่งระหว่าง pro-competitive safety collaboration กับ collusion แบบ per se illegal ภายใต้ Sherman Act §1.
**ผู้เชี่ยวชาญด้าน AI:** สิ่งที่เป็นเนื้อใน "several weeks of engagement" น่าจะครอบคลุม **shared evals + pre-release audit + independent testing framework + standardized safety protocol** ตามที่ leak มา — เท่ากับสร้าง soft-law layer เหนือ EU AI Act ที่บังคับ frontier model provider โดย compliance ไม่ต้อง refer ถึง regulator. คำถามคือ compute-threshold ที่ใช้จะเป็น 10^25 FLOP (EU AI Act GPAI systemic risk) หรือขยับสูงกว่า.
**โปรแกรมเมอร์มืออาชีพ:** short-term ผลกระทบเล็ก — แต่ **release cadence** อาจช้าลง 1–2 quarter เพราะ pre-release audit เพิ่ม step; ทีมที่พึ่ง API ควร (1) lock-in current pricing tier ผ่าน enterprise contract ถ้ามีความเสี่ยง price/latency shift, (2) เพิ่ม provider abstraction layer ใน production stack เพื่อรอง safety-driven feature drift ที่จะเกิดกับ OpenAI/Anthropic/Google พร้อมกัน.

## 3. Exein ระดม $270M — physical AI security ยูนิคอร์นใหม่ของยุโรป

**อาจารย์ (มหาวิทยาลัย):** เหมาะสอน **embedded systems security + IoT threat model** — Exein ทำงานที่ firmware/runtime layer บน 2B+ device (industrial robot, drone, autonomous vehicle, medical equipment) เทียบกับ traditional endpoint EDR ที่ทำบน OS layer; นักศึกษาต้อง trace attack surface ที่ต่างกันระหว่าง edge-inference LLM/VLM บน robot arm กับ traditional PLC/SCADA.
**ผู้เชี่ยวชาญด้าน AI:** "physical AI" = **VLA (Vision-Language-Action) model + embodied agent** ที่รันบน device เอง — attack vector ใหม่ที่ Exein น่าจะ cover คือ (1) prompt injection ผ่าน sensor input (adversarial patch บน camera feed), (2) model weight tampering ที่ firmware, (3) tool-use hijack ผ่าน MCP-like protocol ที่รัน on-device. Valuation 30x ใน 2 ปีพร้อม ARR 4x YoY แสดงว่า enterprise buyer ให้ความสำคัญกับ physical-AI attack surface มากขึ้นชัด.
**โปรแกรมเมอร์มืออาชีพ:** ถ้าทีมทำ robotics / IoT / autonomous — pattern ที่ควรใช้แบบเดียวกัน: (1) sign firmware image และ verify signature ก่อน runtime load, (2) sandbox model inference process แยกจาก actuator control path, (3) log tool-call จาก on-device agent ไป central observability. Exein $270M แสดง market signal — expect vendor tooling หลากหลายในปีถัดไป, อย่า lock-in early.

## 4. AIUC ก่อตั้งโดยอดีต Anthropic + METR — บริการ safety สำหรับ enterprise AI agent

**อาจารย์ (มหาวิทยาลัย):** เคสนี้ดีในคาบ risk management + insurance economics — **"Underwriting"** ในชื่อบริษัทไม่ใช่ metaphor ล้วน — Kvist และ Dattani น่าจะสร้าง actuarial-style model ที่คำนวณ **residual risk ของ AI agent deployment** พร้อม indemnity product. ให้นักศึกษาเทียบกับ cyber insurance (Coalition, At-Bay) ในการ transfer risk ที่ AI agent misbehavior สร้าง.
**ผู้เชี่ยวชาญด้าน AI:** ความสำคัญเชิงเทคนิค — METR (ที่ Dattani เป็น COO) เป็น evaluator ชั้นนำที่ Amodei เสนอในบทบาท "embedded third-party evaluator". AIUC น่าจะขาย **capability-based safety guarantee** — เช่น "agent นี้ทำ actuarial-verified rate ของ prompt-injection compliance ที่ X%" — เป็น product ใหม่ที่แยกจาก generic guardrail (Lakera, PromptArmor). Customer list (Cursor, Lovable, Harvey, ElevenLabs) แสดง target ที่ agent-heavy บน production traffic ใหญ่.
**โปรแกรมเมอร์มืออาชีพ:** ทีมที่ deploy agent บน production — **AIUC-style third-party audit จะกลายเป็น requirement ใน enterprise procurement ภายใน 6–12 เดือน** เหมือน SOC 2 กับ SaaS; เตรียม (1) instrument tool-call log ให้ audit-friendly (structured, replay-able), (2) จอง capability testing ในช่วง release freeze, (3) แยก safety-critical path (financial transaction, PII access) ไปที่ deterministic wrapper ที่ audit ง่ายกว่า agent-loop.

## 5. Salesforce เปิดตัว AIforce ที่ Dreamforce — ใช้ Salesforce จาก Claude/Slack/AI ตัวไหนก็ได้

**อาจารย์ (มหาวิทยาลัย):** ในคาบ enterprise software architecture ให้อ่าน AIforce เป็นตัวอย่าง **headless SaaS pattern** — บริษัทเก่าปรับโครงสร้าง code base ให้ทุก function เปิดผ่าน MCP/API เพื่อให้ AI interface (Claude, Slack) เรียกใช้ได้; เทียบกับ headless CMS ยุค 2010s (Contentful, Strapi) แต่ scope ใหญ่กว่ามาก.
**ผู้เชี่ยวชาญด้าน AI:** เทคนิคที่ Salesforce ทำคือ **MCP server + Skill library + prebuilt authentication** — ลด friction ในการเชื่อม CRM data กับ agent จากที่ต้องเขียน integration เอง 1–2 sprint เหลือ point-and-click. Claudeforce เป็น **strategic bet** ว่า Anthropic จะเป็น primary agent platform ในระยะ 2 ปี — เทียบกับ ChatGPT connector (OpenAI) และ Google Workspace Gemini ที่แข่งกันในพื้นที่เดียว.
**โปรแกรมเมอร์มืออาชีพ:** ทีมที่ใช้ Salesforce (หรือ SaaS อื่น) — pattern ที่ควรทำ (1) รอ MCP server ทางการก่อน build custom integration เอง เพราะ vendor จะออก headless toolkit ใน 6 เดือน, (2) ถ้าต้องเชื่อม CRM กับ Claude workspace ตอนนี้ให้ใช้ Claudeforce path แทน manual API glue, (3) audit permission scope ของ MCP server ที่ enable — role-based access ที่ Salesforce provider หลุด ไปที่ agent อาจเปิด lateral movement risk บน tenant.
